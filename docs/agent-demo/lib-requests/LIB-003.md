# LIB-003: approvalを別HTTPで再開するとStream検証状態が失われる

状態: fixed（app初回統合成功の報告受領済み）  
担当: `/root/stream_library`  
アプリをブロックするか: yes（標準useChat approval continuation）

## 契約・最小再現

installed `ai` 7.0.92 / `@ai-sdk/react` 4.0.95の標準フローは、
`tool-input-available` → `tool-approval-request` → `finish-step` → `finish` → `[DONE]` で待機する。
`addToolApprovalResponse` は同じassistantのtool partを `approval-responded` にし、
`lastAssistantMessageIsCompleteWithApprovalResponses` を `sendAutomaticallyWhen` へ渡すと別HTTPへ送る。
後続streamは既存の同assistant/toolへ `tool-approval-response` / `tool-output-available` 等を適用できる。

旧Streamで最初のfinish後に続けると `FinishedError`。新Streamでstart/stepの後にresponseだけ送ると
`approval ... has not been requested`、outputだけ送ると `tool invocation ... has not been declared` になる。
Eventのwire schema自体はSDKと一致している。これはSDK制約ではなく、別HTTPの検証状態復元APIがないlib不足。

## 最小修正

`Stream.new(sink = nil, continuation: saved_events)` を追加。
server保存の `Enumerable<Event>` を同じ遷移検証に通してtool/approval状態を復元する。
初期化はframeをemitせず、toolも実行しない。過去HTTP区間は各 `finish` で終了していることを要求し、
不正な順序、未完了、abort/errorは拒否する。複数の完了区間も同じassistantの履歴として復元できる。

callerは元のassistant IDを指定して `start` / `start_step` を送り、承認response、tool outputまたはdenied、
`finish_step` / `finish` と続ける。`continuation:` 省略時は既存契約を維持。
本人・会話・確定引数のbinding、判断永続化、陳腐化・重複の処理、DB副作用の一度実行はアプリ責務。
client提出の履歴をそのまま信頼して復元してはならない。

01 / Before

text deltaだけなら、Railsから直接流せる。

Railsは一つのHTTP responseを開いたまま、RubyLLMのchunkごとにSSE frameを書く。Stimulusはresponse bodyを読み、受信したdeltaをDOMへ追加する。

RubyLLM::ChunkのcontentをRailsがSSE frameへ変換する。

Rails: SSEを書き出すchat_streams_controller.rb
class ChatStreamsController < ApplicationController
  include ActionController::Live

  def create
    response.headers["Content-Type"] = "text/event-stream"
    response.headers["Cache-Control"] = "no-cache"
    response.headers["X-Accel-Buffering"] = "no"

    RubyLLM.chat.ask(params.expect(:prompt)) do |chunk|
      next if chunk.content.blank?

      event = JSON.generate(delta: chunk.content)
      response.stream.write("data: #{event}\n\n")
    end

    response.stream.write("data: [DONE]\n\n")
  rescue ActionController::Live::ClientDisconnected, IOError
    Rails.logger.info("chat stream disconnected")
  ensure
    response.stream.close
  end
end
Stimulus: 受信したdeltaをtextへ足すcompletion_controller.js
async submit(event) {
  event.preventDefault()
  this.outputTarget.textContent = ""

  const response = await fetch(this.element.action, {
    method: "POST",
    body: new FormData(this.element),
    headers: { Accept: "text/event-stream" },
  })

  for await (const event of readSSE(response.body)) {
    if (event.data === "[DONE]") break

    const { delta } = JSON.parse(event.data)
    this.outputTarget.append(delta)
  }
}

readSSEはdecodeとframe境界の処理を隠した説明用helper。ここで見たい本質は、受信したevent.dataからdeltaを取り出し、textへ追加する部分だけ。

textだけなら、これで十分に小さい。問題はdataが文字列ではなく、Agent execution stateになったときに始まる。

04 / Rails implementation

Controllerに残るのは、HTTP lifecycleとAgent実行。

adapterのheaderを最初のwriteより前に設定し、RubyLLMのchunkを渡す。client Stopによるsocket切断と、provider例外によるprotocol errorは別の経路として扱う。

Rails controllerchats_controller.rb
class ChatsController < ApplicationController
  include ActionController::Live

  def create
    stream = nil
    stream = RubyLLM::Stream::AISDK.new(
      response.stream,
      message_id: assistant_message_id
    )

    stream.headers.each do |name, value|
      response.headers[name] = value
    end

    chat = RubyLLM.chat
    chat.after_message do |message|
      stream.write_message(message) if message.tool_result?
    end

    chat.ask(user_prompt) do |chunk|
      stream << chunk
    end

    stream.finish(finish_reason: :stop)
  rescue ActionController::Live::ClientDisconnected, IOError
    Rails.logger.info("AI SDK client disconnected")
  rescue StandardError => error
    Rails.logger.error(error.full_message)
    terminate_failed_stream(stream)
  ensure
    response.stream.close
  end
end

06 / Terminal semantics

07 / Final architecture

Railsを捨てず、Agent streamingだけを分ける。

Reactへの全面移行ではない。通常のWeb UIはRails/Turboに残し、複雑なmessage stateを持つ領域だけをReact islandとuseChatへ渡す。

通常のinteraction

server rendered HTMLが自然な領域

  1. Rails model / controller
  2. Turbo response
  3. HTML partial
  4. DOM update
同じ
Rails app

Agent streaming

client state machineが価値を持つ領域

  1. Rails + RubyLLM
  2. AISDK adapter
  3. useChat reducer
  4. React island

Railsにstreamがないのではない。
足りなかったのは、Agent eventとclient stateの間にある境界だった。

通常のUIはTurbo。複雑なAgent streamingだけはuseChat。
